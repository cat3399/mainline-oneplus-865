# First sustained ONLINE test with the unified X55 runtime

Date: 2026-09-29 (+08:00). Kernel: `6.16.7-kebab-x55-r5+`, slot A.
Boot ID: `835bdbd0-bf46-47fc-9591-4ea8d664c011`.

**Result: the >=10-minute ONLINE/USIM/LTE-registration gate passed on this
boot. No ERRFATAL, modem restart or host reset was observed. This is not a
successful LTE data test or proof of long-term reliability.** A subsequent
explicitly authorized data test on the same boot is recorded separately in
[DATA-TEST-2026-09-29.md](DATA-TEST-2026-09-29.md); the no-bearer statements in
this earlier record refer only to the stability phase.

## Controlled setup

The user performed the planned host reboot. ESOC was initially offline, all
four services inactive, no attempt marker, and no preloaded Sahara module.
The r5 module (`kebab-oemnv-1`), controller, native helper, EFS service and
repaired TFTP binary matched the staged hashes. The module actually loaded
with the expected policy version. Recovery was disabled before the sole
manual remoteproc start and remained disabled.

Persistent kernel, MHI/DIAG, userspace and SSCTL captures began before boot.
The private wrapper was invoked with automatic ONLINE disabled; the operator
then made one normal ONLINE transition. No identity value or check was added
to scripts. The existing private manual identity query matched the prior
own-device result. No firmware, kernel image, boot slot, raw NV, bearer or
host routing changes were made during this test.

## Remaining caveats

- Earlier r4 failures occurred roughly 100–129 seconds after mission mode.
  The first successful EFS exchange began about 90 seconds after mission
  mode on this boot. This is strong timing evidence for the missing runtime
  synchronization path, but **not a single-variable causal proof**: the r5
  bundle also includes the stock OnePlus image-20 override.
- MHI remained M0 (M0=1, M2/M3=0); modem MHI MSI counters remained zero while
  the existing polling fallback operated. Neither IRQ delivery nor runtime
  PM/suspend has been validated by this result.
- TFTP FDs stayed between 4 and 8; sampled RSS remained approximately 1824 KiB
  with one thread. DIAG captured no payload. The SSCTL trace contained no
  host shutdown call.
- WDS remained **disconnected**; both `mhi_hwip0` and `mhi_swip0` stayed down.
  No WDA format change, WDS Start Network, APN/band override, IP address,
  route, DNS or connectivity test was attempted.
- Warm recovery is still unvalidated. The one-attempt-per-boot guard is not
  relaxed. The bounded file-only EFS service is not a production NV replay or
  archival policy; original Android backup writers remain disabled.

## Handoff

The modem is left **ONLINE** with all four manual services active, so the
next data-plane investigation can use this healthy session without a blind
warm restart. They remain static/not boot-enabled; recovery stays disabled.
The 900-second recorders and read-only query watch completed successfully.
No further reboot or automatic recovery is scheduled.

Next work is to establish the correct PCIe WDA/WDS endpoint and use a
persistent client for binding/start/status/stop, then an isolated LTE bearer
test without changing the working host network. Separate QRTR qmicli
processes plus a reused CID must not be assumed to preserve one WDS client.
