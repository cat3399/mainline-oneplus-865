`835bdbd0-bf46-47fc-9591-4ea8d664c011`. The user authorized a data call and

## Result

**LTE IPv4 data works in this test:** a persistent WDS client bound to the
PCIe endpoint, started the existing CMNET profile, received IPv4 settings,
completed DNS/ICMP/HTTPS transfers, and cleanly stopped its own call. There
was no observed ERRFATAL, modem restart or host reset. This is a short,
bounded data test, not a claim of production reliability or peak throughput.

Domestic results below used a byte-range GET of exactly 8,388,608 bytes of
`/ubuntu/ls-lR.gz`, discarded rather than executed or installed. Both servers
returned HTTP 206, matching Content-Range and Content-Length. Transfers were
not rate-capped, and curl was explicitly bound to the cellular interface.

## Wi-Fi isolation and verification

- Root namespace Wi-Fi stayed on `wlp1s0`; its default route was never changed.
- Only the previously-down `mhi_hwip0` was moved into a new `x55-data`
  namespace. QMAP mux 1 was represented by `x55rmnet0` there. No Wi-Fi device,
  veth, bridge, NAT or forwarding path was added to this namespace.
- IP, gateway, MTU and DNS came from the modem's **same WDS client** and were
  applied only inside the namespace. DNS was stored in
  `/etc/netns/x55-data/resolv.conf`, not the host's resolver file.
- Every network test used `ip netns exec x55-data`, IPv4,
  `--interface x55rmnet0`, `--proxy ''` and `--noproxy '*'` for curl. Route
  lookups and curl's local address confirmed cellular egress, while root
  namespace route lookups still selected Wi-Fi.
- Host IPv4/IPv6 routing tables and policy rules compared byte-for-byte
  unchanged. Host `/etc/resolv.conf` checksum was unchanged.
- Wi-Fi gateway monitoring during the domestic download returned **30/30
  packets**, 0% loss, average 6.8 ms. This establishes preserved connection
  and routing, not a claim that RF coexistence can never affect Wi-Fi rate.

## Endpoint and protocol evidence

1. ModemManager's `mm-port-qmi.c:initialize_endpoint_info()` specifies the
   Qualcomm PCIe interface number **4**. libqmi defines PCIe type **3**.
2. The modem accepted `--wda-get-data-format=ep-type=pcie,ep-iface-number=4`,
   unlike the earlier unqualified query. Its initial format was raw IP with
   aggregation disabled.
3. WDA Set/Get then confirmed raw-IP link layer with **QMAP in both
   directions**, DL max 8 datagrams / 16384 bytes. UL negotiated max 1
   datagram / 64512 bytes. The parent MHI MTU/MRU was kept at 16384; rmnet's
   IP MTU was the modem's 1500.
4. Existing profile **3** was read back as CMNET, default APN, IPv4-or-IPv6.
   The test requested IPv4 with that profile. No APN/profile/band/PIN data
   was rewritten.
5. The new `wds_session.py` kept **one AF_QIPCRTR socket** for status, Bind Mux
   Data Port, Set IP Family, Start Network, Get Current Settings, periodic
   status and Stop Network. It never relied on CID reuse across qmicli
   processes. Bind used endpoint `(PCIE, 4)`, mux 1 and tethered client type.
6. Successful start/settings were recorded at uptime **2522.64 s**; normal
   Stop Network completed at **3329.51 s**, on the same socket and owned
   packet handle. Subsequent DMS/UIM/NAS/WDS queries still showed ONLINE,
   ready USIM, registered LTE and disconnected packet service.

Wire definitions were reviewed against libqmi 1.34.0, commit
`3f07d6e5b4677558543b3b4484ea88ad92257e92`; relevant schema and QRTR transport
sources, the ModemManager endpoint source and Apollo bearer patches are
saved privately with the test. The ten new isolated regression tests cover
wire bounds, endian conversion, settings validation, persistent lifecycle,
matching transactions, unsolicited indications, errors/timeouts without
retries, hardware-health gating and exclusive private status files.

## Tool limits and handoff

`wds_session.py` is an explicit bring-up tool, not a boot daemon or a general
connection manager. It performs no link, DNS or routing changes itself. It
requires healthy ESOC/RFS/EFS, checks every control exchange, discovers the
unique WDS/DMS node, allows one Start per client, and never sends a wildcard
Stop. `status` queries a newly allocated client, not another process's call;
the exclusive lock prevents such a query during this tool's active session.

The start action requires a reviewed `--profile`; the documented test used
`start --profile 3 --mux 1 --endpoint 4 --hold-seconds 900`. Normal timeout or
SIGTERM stops the owned call. If a known call fails, the socket is parked for
operator review rather than sending speculative Stop/Start/reset commands.
For supervised systemd use, set `Restart=no`, `SendSIGKILL=no` and a stop
timeout longer than the QMI deadline so a failed Stop is not converted into
an unconditional client kill. No automatic reconnect or modem restart exists.

The test call is now **stopped**. The modem and all four runtime services
remain ONLINE/active, with recovery and boot auto-start disabled. Both data
interfaces in `x55-data` are down; the namespace/config/state are deliberately
preserved for inspection, and root Wi-Fi continues to carry normal traffic.
The PCIe endpoint remains in the negotiated QMAP format. No persistent host
network manager configuration, kernel/firmware update or boot-slot write was
made. Successful data-call teardown is **not** validation of modem warm SSR.
